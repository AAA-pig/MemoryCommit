# 记忆账本（astrbot_plugin_memory_commit）

一个**外置**的记忆插件：记忆不躺在 AstrBot 的数据库里，而是单独一份 SQLite + 一份能直接翻的 Markdown，换插件、换版本、换机器都还在。

设计上是两个模型拼起来的。

## 一、lsby/ai-memory 给的骨架：不会乱、能回放

1. **写入只能发生在「提交」里**
   每次 insert / update / delete 都得先进一个提交。提交的父节点必须正好是当时的 HEAD，否则直接拒绝——等于拿数据库本身做了一次 CAS。
2. **行级快照**
   一个提交挂一串 `commit_row`，按「提交内序号」严格排序，记下每行的 before / after。任何一次改动都能查到「改前是什么、改后是什么、属于哪个提交」。
3. **HEAD 展开成当前状态**
   当前记忆表 = 从第一条提交重放到 HEAD 的结果。所以 `materialize("C3")` 能拿到「C3 那一刻」的记忆全貌。
4. **信息冲刷**
   `冲刷量 = 当前最大创建序号 − 该记忆的最后访问序号`
   两个单调递增的序号一减，就是「自上次碰它以来，系统又经历了多少新信息」。休眠一个月没有新记忆产生，冲刷量是 0，一点不掉。
5. **保留指数**
   `R = 初始重要性 × (1 + log2(1 + 线索数)) × (1 + log2(1 + 访问次数))`
   冲刷压力 `= 冲刷量 / (R × 6)`，`>= 1` 才降一级；降到零级再超才淘汰。一次只降一级。

## 二、biyuehu/animaone 给的皮肉：记得住、找得回

1. **时间粒度分层**：`topic / day / week / month / quarter / year`。`topic` 和重要性 ≥ 0.85 的记忆被**钉住**，不参与自动冲刷。
2. **标签即概念，自动织网**：写入时带 `tags`，和历史上共用同一概念的节点自动连边（`memory_link`）。检索命中的节点会沿边带出邻居，唤起时最多走两步。
3. **中文无词典切词 + BM25 + 30 天半衰期**
   双字滑窗切词，BM25（k1=1.5, b=0.75）打分，再乘 `0.5 ** (天数/30)` 做时间衰减。单字查询（「辣」）在 BM25 里必然空手，会回退成子串命中兜底。
4. **越常用、越慢忘**
   半衰期不是常数：`effective_half_life()` 按访问次数 `1 + log2(1+n) × 0.5` 拉长，封顶 5 倍。被反复想起的事在时间里站得更久，但热点记忆也不会永远不淡。和冲刷那边的保留指数分开算——一个管「排多靠前」，一个管「会不会被降级」。
5. **画像层单独放**：`preference / identity / event / relation / dislike`，同一件事重复提到会累加权重。

## 三、最要紧的一环：唤起（检索 → 联想 → 激活）

两位前辈的东西，真正值钱的不是存得住，而是**在关键时刻被想起来**。只写不读，账本就是个单向黑洞。所以每次请求大模型前，`on_llm_request` 会先唤起一轮，压成一小段塞进系统提示：

1. **检索**：拿当前这句真实的话去 BM25 + 时间衰减里找，命中的才算「直接想起来」。撞上稀有线索（「端口」只挂在一条记忆上）会把这条往上抬最多 60%，撞上「日常」这种满地都是的线索几乎不动——线索权重是直接加在主打分上的，不是只在联想那一路补位。
2. **联想**（他们真正的精髓在这里）：不是记忆连记忆，而是**线索当枢纽**。
   - 一句话里的词先撞上「线索」（`clue`），线索再把挂着它的记忆牵出来——查询 → 线索 → 记忆。
   - 线索按 **IDF 加权**：只挂在两三条记忆上的线索权重接近 1，「日常」「聊天」这种满地都是的线索压到 0.1。所以撞上「空调」能牵出具体那件事，撞上「日常」牵不动什么。
   - 再沿概念连边往外走，**最多两步**（甲 → 乙 → 丙），每多一步分量减半；只有真被想起的节点才值得再往外走一步。
   - 想不起来就老实承认想不起来。正常聊天里没命中，一字节都不注入——人也不会每句话都翻旧账。
3. **激活**：没有具体问题的时候（主动搭话），让「新鲜 × 重要 × 巩固」自己排，挑一两条冒出来。这是 animaone 那只凌晨做梦的做法，只不过我们只借了排序，没让它半夜乱说话。
4. **闪现线索**：结果里除了记忆，还带出「顺着这些词想到的：熬夜、代码」。这是给模型看的联想路径，它自己知道为什么想起这件事。

几条分寸：

- **冷却**：同一条记忆 25 分钟内不重复浮现。不会每轮都念同一件事。
- **检索落空（fallback）**：有检索词却一条都没命中时，降级让「新鲜 × 重要」的记忆冒出来
  （数量最保守，只取 `limit//2` 条），`route` 标 `fallback`。兜底全被冷却挡光就标
  `fallback_blocked`，跟「根本没走检索」的 `none` 分得清。fallback / activate 不算
  「被想起」，不会进复出判定。
- **预算**：注入总长默认 420 字，宁可少说。
- **画像节流**：`profile` 那层一小时才注入一次（`JJ_MEMORY_PROFILE_REFRESH` 可改）。
- **唤起即访问**：被想起来的记忆会 `touch`，延后遗忘——这正合「常用才记得住」。
- **不挡聊天**：唤起抛任何异常都只记 warning，绝不影响正常回复。

## 三半、两件「顺手」的事

不是核心机制，但缺了会难受：

- **每日导出**：每天第一次请求前，顺手把 `记忆账本.md` 刷一遍。不挂定时器，跨天才写，同一天再调直接跳过。
- **自动压缩**：提交数超过阈值就顺手压一次（默认关，设 `JJ_MEMORY_AUTO_COMPACT=40` 开启，保留条数用 `JJ_MEMORY_AUTO_COMPACT_KEEP`）。压缩写在事务外面，失败只记警告，绝不让已经成功的写入跟着报错。

## 三又半、分级终于开始转：工作记忆容量

`grade` 字段一直都在，但一直没有机制去动它——所以它只是装饰。现在给它一个容量：

- **二级 = 巩固层**：不占名额，也不参与挤出。
- **一级 = 工作记忆**：名额有限（默认 3，`JJ_MEMORY_WORKING_CAPACITY`）。满了就把排名最靠后的挤到零级。
- **零级 = 沉降层**：不主动冒头（自动激活里权重打 `ZERO_GRADE_WEIGHT` 折），但检索照样找得到；想回到一级，得在最近 3 天里被想起 `REVIVE_HITS`（默认 2）次。

排名看的是「此刻有多清楚」：`(0.4 + 重要性) × 时间衰减 × 最近碰没碰过 × 最近被想起几次`。第三项把「多久没被想起」（冲刷用的）换成「上一次被想起距今隔了几件事」——隔了十来件事还没人提它，就该让位了。

换班一次算清：现有的和该复出的放同一张榜上抢名额，不会出现先降后升、下轮又降的来回打。变化照旧走提交，降级和复出都能回放。每轮最多挤 `WORKING_DEMOTE_LIMIT`（默认 20）条，分期收敛，免得一条提交里塞两百行快照。

挂在每天第一次请求上顺手跑（有 6 小时冷却，没超员什么都不做），也可以 `/记忆容量` 手动看、手动执行。

## 三又半、原文链与注入观测账

- **原文链（原话）**：把用户原话和助手回复原样落成一条哈希链，一个节点吃上一条的
  `digest`——改一个字、中间断过、尾部被删都会在 `verify_message_chain()` 里露出来。
  故意不进提交链，免得一天几百条消息把「记忆的历史」稀释成流水账。查原话用
  `/记忆原话 [关键词]`：候选先取最近 `SEARCH_CANDIDATE_CAP`（200）条做 BM25，没找到会
  扩窗到 `SEARCH_EXPANDED_CAP`（2000）再试一遍；再找不到就告诉你「原文链共 N 条、
  只查了最近 M 条」，不会让你以为「没说过」。
- **注入观测账**：每次请求大模型前把「这轮注入了多少、丢了多少、预算用掉多少」记一行
  到 `inject-log.jsonl`，只用来观察 420 字够不够，不碰任何行为。超过
  `INJECT_LOG_ROTATE_LINES`（5000）行自动轮转成 `inject-log.1.jsonl`，不重写、不删老账。

## 四、表

| 表 | 作用 |
|---|---|
| `mcommit` | 记忆提交（id / parent / message / created_at） |
| `commit_row` | 提交内的行级快照（提交内序号 / 表 / 操作 / before / after） |
| `memory` | 当前记忆（层级 / 等级 / 重要性 / 摘要 / 标签 / 创建序号 / 最后访问序号 / 访问次数） |
| `clue` / `memory_clue` | 概念线索，内容 UNIQUE，靠关联表挂到各处 |
| `memory_link` | 概念关联边（from / to / concept / strength） |
| `profile` | 画像事实 |
| `core_rule` | 底层法则（预留） |
| `access_log` | 访问痕迹：什么时候、因为什么被想起。**不进提交链**，只喂衰减计算 |
| `message` | 原文链：用户消息一个节点，`digest` 哈希链锁起来，改一字整条对不上。不进提交链 |
| `meta` | HEAD、各类计数器、`schema_version`（跟着库走的结构版本） |

## 七、已知边界

- **检索是词面匹配，没有语义向量，这是结论不是待办。** 同义不同词会漏（「空调」找不到「制冷」），这是刻意的取舍：不依赖 embedding 服务，断网也能用，单机跑不额外吃内存。哪天真要上向量，从 `tokenize()` 和 `_bm25_scores()` 这两处替换即可，表结构不用动。
- 自动织网只按标签字面相同连边，不做语义相似边。
- 压缩只动历史，不动当前状态：`/记忆压缩` 把最早的提交重放成一条 `C0` 基线，再保留最近若干条。压缩后 `materialize` 到保留的提交，结果和之前一模一样；被压掉的提交不再单独存在。
- 一次冲刷一条记忆只降一级，避免一次掉太多。
- `materialize()` 传一个不存在的提交号会抛 `LedgerError`。以前静默返回空表，跟「那一刻真的没有记忆」分不清，也不好查调用侧的 bug。
- 自动压缩默认关闭：它只是「顺手」，压不压由人决定；开启后也只在写入完成后触发，不打断写入。
- 结构版本只升不降：库比代码新时直接抛 `LedgerError`，不给「勉强打开」这个选项。
- 访问痕迹和账本内容分开：`access_log` 记「被想起」的明细，`memory.access_count` / `last_access_seq` 只是喂衰减的缓存。两者都不进提交快照——想起一件事不等于改写一件事，浮现一万次，账本厚度不该变。
- 访问日志会自己收：每日导出之后顺手修剪，默认留最近 180 天、每条记忆至少留最近 200 次。热度已经落到 `memory` 表，删日志不丢强度。
- `load_jsonl()` 默认只肯往空库灌。覆盖是破坏性操作，得显式传 `replace=True`。

## 八、搬家：怎么脱离 AstrBot

这层从一开始就按「以后要自己走」来长的，现在把它做完整了。

**分层是死的**：`ledger.py` 只 import 标准库，一行 `astrbot` 都没有；`main.py` 只做适配（读事件、挂指令、把提示词拼好）。所以换宿主时 `ledger.py` 原样带走，重写一个几十行的外壳就行：

```
收到消息     → ledger.remember(...)
请求模型之前 → ledger.activate(query) + ledger.render_brief(...)
要改配置     → ledger.remember_profile(...)
```

**结构版本**：`meta.schema_version` 跟着库走，不跟代码走。老库没这个键会被认成 0 号，自动升到当前版本（升之前不碰任何投影表）。现在是 v4——补了 `message` 表的 `seq` 索引，老库一路只做加法迁上来。反过来，**库比代码新就拒绝打开**——迁移是单向的，硬开只会把新列悄悄丢掉。

**dump / load**：`/记忆备份` 写一份 JSONL，头一行是文件头（格式名、格式版本、结构版本、接口版本），之后一行一条记录。

```python
led.dump_jsonl("backup.jsonl")          # 整本账：meta + 提交链 + 提交行 + 所有投影表
new = Ledger("别处.db")
new.load_jsonl("backup.jsonl")          # 默认只肯往空库里灌
new.load_jsonl("backup.jsonl", replace=True)   # 要覆盖得自己说
```

导出时会跳过 `last_export_date` 这类「这台机器此刻的状态」——那个属于机器，不属于账本。导入时会丢掉备份里多出来的列并计数（老宿主加过的字段不至于让整次导入失败），导完补跑一次迁移，最后校验 HEAD 在不在提交表里。

**核对**：迁移前后各跑一次 `health_check()`，再用 `materialize(head)` 抽样比对。真库副本上演练过：15 个提交、5 条记忆、13 个线索、9 条连边，搬完一条不差，还能接着写。

**宿主契约**：下面这些是公开接口，`CORE_API_VERSION` 管它们；改签名就得升这个号。其余方法都是内部件，外面不该调。

| 方法 | 用途 |
|---|---|
| `remember / forget / remember_profile` | 写 |
| `recall / activate / render_brief` | 读（唤起） |
| `profiles` | 画像 |
| `flush / compact / stats / health_check` | 维护 |
| `dump_jsonl / load_jsonl` | 搬家 |
| `materialize / history / show_commit` | 回放与追溯 |
